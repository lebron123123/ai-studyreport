# 0910 存储升级操作单

## 本地电脑 / 服务器

PostgreSQL保存结构化数据和研究内容块；原件经现有鉴权RAG_OBJECTS接口进入磁盘。`RAG_OBJECT_ROOT`指定持久目录，默认`local-data/rag-objects`。本地磁盘与未来服务器挂载卷使用同一接口。目录不得配置成无鉴权静态目录；发布包不包含.env、业务数据库或原件。

未来迁移必须同时迁数据库与对象目录、配置权限和持久挂载。不要只复制网页或只备份数据库。不依赖服务器连接GitHub，可以经内网传输核实版本的部署包。

## 升级顺序

1. 暂停编辑，记录当前版本。运行现有backup-project.mjs，核对数据库和原件manifest。
2. 运行verify-backup-restore.mjs恢复到独立库，读回验证，不覆盖业务库。
3. 本机执行`node --env-file=local-server/.env local-server/migrate-research-storage.mjs <保护备份目录>`。脚本只允许本机数据库；未来服务器的0036增量SQL由管理员在相应环境核准，不修改保护脚本绕过限制。
4. 先部署支持旧JSON和新manifest双读的服务，再部署前端。确认8080仅一个服务，正常网络权限重启。不要再启动第二个占用相同端口的服务。
5. 检查站点、完整研究读写、冲突、真实生成、相邻项目API后开放编辑。

## 回退

保留新读取器，可用`RESEARCH_STORAGE_V2=0`关闭新分块写入，然后重启、验证旧协议。**不能直接退回不认识research-parts-v1的旧程序**；功能开关不是数据库逆迁移。

如需整库恢复，先停写并另备份升级后的数据库和对象，明确恢复点以后的差异，经确认再一起恢复。不得删0036表、原件或冲突副本来试错。
