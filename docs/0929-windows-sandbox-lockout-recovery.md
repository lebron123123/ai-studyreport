日期：2026-09-29。本地工作树；未提交、推送或部署。本记录不含密码、沙箱秘密、浏览器资料或完整个人安全日志。

## 结论与范围

1909 是 Windows 拒绝启动已经锁定的沙箱账号，不会自动删除或回退项目代码。当前本机 Edge 154.0.4258.37 的启动缺陷已通过复现确认：浏览器启动会对当前 Windows 用户提交错误密码探测，重复启动累积到系统锁定阈值。

依据为 Microsoft 官方问题 https://github.com/MicrosoftEdge/WebView2Feedback/issues/5722 及其关联的 Chromium 问题 https://issues.chromium.org/issues/541310282 。本机近 7 天读到 241 次沙箱账号错误密码事件、12 次锁定，调用方均为官方路径 Edge。不能仅凭进程名认定个人浏览器扩展有问题。

本次是项目浏览器测试启动路径的针对性规避，不是浏览器厂商永久修复，也没有改变个人 Edge / 外部 WebView2 程序的启动方式。

## 实现与防复发

- scripts/windows-browser-lockout-guard.cjs：Windows 测试进程启动 Playwright Chromium/Edge 时合并 `--disable-features=AutofillAiWalletPrivatePasses`。覆盖普通与持久化启动，非 Windows 不变，重复安装不重复包装。
- package.json：npm test 与新增 browser:safe 入口加载防护。
- scripts/run-postgres-tests.mjs：完整真实数据库回归的子测试进程也加载同一防护，不在各测试文件复制。
- tests/windows-browser-lockout-guard.test.cjs：验证选项不被原地改写、已有 feature 参数合并、非 Windows 不改变、两种启动路径、调用对象保留和幂等。
- scripts/probe-browser-lockout.cjs：仅供人工受控对照。未规避的 baseline 只先启动一次，接近锁定阈值不重现。
- scripts/diagnose-codex-lockout.ps1：需要管理员批准，只读必要安全事件/进程/账户状态，写入明确的新诊断文件，拒绝覆盖及静默吞掉权限错误。
- agent.md：优先检查新日志与已确认的上游缺陷，不再先要求退出个人 Edge；禁止靠重置密码、清除凭据、关闭锁定策略或降低隔离来掩盖问题。

今后单独执行浏览器脚本使用 `npm run browser:safe -- scripts/脚本名.mjs` 或 `node --require ./scripts/windows-browser-lockout-guard.cjs ...`。直接 raw node 启动未防护浏览器仍可能复发。浏览器更新后也先核对新安全日志再考虑移除规避。

没有关闭个人 Edge，没有修改 Windows 密码、锁定阈值、Codex elevated 隔离、网站公式或用户项目资料。无需重启业务服务，因为未改业务运行链路。
