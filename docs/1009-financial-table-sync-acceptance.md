# 1009 重新生成正文时财务表同源修复：技术验收

证据日期：2026-10-09。适用版本：本机当前未提交工作区，财务表模块 `calc-tables-v1`。本记录是技术验收，不是正式项目财务审签、完整报告专业认证或发布证明。旧稿问题及只读证据见 `docs/1009-sandbox-and-two-report-audit.md`；评分增量见 `docs/1009-report-audit-capability-review.md`。

## 1. 问题与本轮边界

税务局旧稿的财务正文已采用当前五年测算，但收入、成本、收益及敏感性表继承了旧版冻结内容。原冻结机制能保护表格不被模型改数，却不能证明被冻结的是当前采用的测算；合并标准表前若仍保留旧原始表，旧年份和旧行还可能被再次合入。

集成核查另发现一项相邻根因：程序生成的真实跨小节表引用经过 `MD.renderHtml` 时被当作普通文字转义，引用段落的稳定身份属性丢失，触发 `bound-reference-missing`。这是渲染/协议消费不一致，不应靠取消必要引用校验或直接删引用解决。

本轮只修正“明确重新生成时采用当前测算重建程序财务表，并把候选稿和采用快照绑定”的链路。不重新计算财务公式，不以AI填数，不自动改项目参数，不修改已保存历史。打开旧稿、预览或导出旧报告不会偷偷刷新正文；只导出旧报告也不能修复其中旧数值。

未执行付费AI全文生成、正式项目写入、部署、服务重启或关闭个人Edge。未修改沙箱隔离或Windows账户策略；本轮不以财务表修复宣称历史1909永久根因已查清。

## 2. 输入、输出与责任模块

| 责任 | 文件/接口 | 行为 |

## 3. 已实现的保护与失败边界

### 3.1 当前测算替换旧程序表

- 严格识别系统/标准的收入、成本、收益汇总、敏感性及现金流表；使用当前结果的真实年份、年度值与汇总值。
- 在 `ReportSectionLayout.composeDocument` 之前同步全部原始entries，防止后续标准表合并重新并入旧年份和旧数值；重复同步结果一致。
- 保留表外叙述及非财务表。人工、独立补充标记表及其受保护容器不自动改数；不把未知业务表猜成系统财务表。生成副本先预扫描所有表，将四类保护标记保留原值并转换为既有独立表保护，提升到承载figure；混合figure整组保留，不因人工表先后顺序而被标准表合并吞掉。冻结时保护标记继承到每张表，JSON恢复后仍生效；原正文不变。
- 来源标签记录测算快照、版本、项目及确定性源身份。构建期未发生的出租率/租价显示“—”，有效年度缺数据不擅自填零。
- 非财务内容不因旧稿别处有财务表而要求采用快照；确有程序财务表却缺少采用源、参数/汇总不匹配、项目身份冲突、必要数据非法或未知程序财务种类时明确阻止，不静默继续保留旧数。
- 敏感性结果不存在时明确待补，不继续沿用旧敏感性情景。

### 3.2 候选与已接受正文隔离

新生成合同只属于对应小节及其完整输出文本；生成新候选不提前覆盖旧正文、旧合同、旧质量回执或历史。返修消费该候选自身的表和合同，不拿已接受旧稿的冻结表覆盖新候选。

首次财务小节没有旧表时，独立绑定当前已采用测算并保存 `completionFinancialSource`；精确文本回执、候选及JSON恢复保留该来源，返修与接受均复核。原有普通表不阻止首次绑定，仅全部明确受保护的人工表免此首绑。无来源的新财务输出仍阻断，旧无来源候选不能借相同输入ID放行；不会伪造空冻结清单或放宽合同。人工保护标记在外层容器时，也随表本身保留，避免只冻结 `table.outerHTML` 后丢失。

候选审查与接受校验财务源身份和输入计划。来源改变导致的准入失败，以及服务器返回的结构/解码失败，不能靠反复“复核”消失。拒绝保留旧正文；接受同时切换对应正文与合同；撤销恢复旧正文及旧合同。

### 3.3 异步及跨小节准入

绑定前后、模型返回后及异步权限复核后，继续检查项目/研究轮次、正文、锁定、候选、规则、输入计划及精确财务源。财务签名覆盖参数、采用快照身份和参数/汇总、年度/月份结果、敏感性及模型版本等；不以一个宽松版本号替代内容校验。

跨小节引用只承认当前已接受文档中的实际目标表，不把同批未接受兄弟候选当作已生效事实。目标表变更或计划变化时拒绝过期结果；需要先接受所属小节时明确提示，不删除防串写校验来放行。

引用渲染补丁仅允许独立的 `p` 段落、五个固定属性、有效可见节号与表身份hash，并要求与程序标准生成的HTML逐字一致；不能携带任意额外结构或属性。`md.js`解析和实际渲染时分别严验，非法/近似引用继续作为转义文字保留，不能借此次修复开放任意HTML。引用显示安全不等于引用获批：清单完整性、来源合同和实际目标表仍由原准入校验负责。`index.html`缓存版本同步更新。

## 5. 用户下一步与验收方式

1. `Ctrl+F5`刷新网站加载本轮前端代码，在项目中确认要作为可研来源的财务测算已被采用；不能只修改未采用的参数草稿。
2. 重新生成财务相关小节，或按已确认篇幅计划重新生成需要更新的正文。已有正式稿的更新仍走可见候选与接受流程，人工独立表需人工核对。
3. 如有跨小节引用，先接受并核对财务表所属小节，再复核、接受引用小节，不能把未接受兄弟候选作为生效事实。确认内容后保存新报告版本，告知项目名和版本号，再由主代理对新版本只读验收：当前采用测算与收入/成本/税/利润/现金流及敏感性逐项核对，核对必要标题、依据分类和业务论证，并实际排版检查页数与目录。

无需仅为验收反复改旧报告或导出旧版；但没有新生成并保存的版本，就不能验收新内容是否合格。默认120页/约7.5万字是生成前规划，不保证固定页数，更不能替代结构、事实与专业分析审查。龙岗协议/测算规模冲突仍须人工确认，本轮没有替用户调整规模。
