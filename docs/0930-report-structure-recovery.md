## 原因与影响

旧结构化段落协议只表达正文职责，整节精简又按职责合并正文，未把业务子标题作为必须保留的结构。历史阅读工具栏缺少选中版本的下载入口。只读税务局报告核对：V9、V10、V11 均为12章43节，非依据业务标题分别70、57、0；不是章节数据全部消失，而是内部标题退化及入口缺失。

## 实现

- `report-completion-contract.js`：可表达三级至六级业务标题，必需标题顺序及层级校验；不同主题可复用正文职责，但共享原字数预算。精简不删除结构。
- `report.js`：当前有标题时沿用，失去标题时匹配本项目自身历史小节，仅提取结构，不复制正文、事实、测算。税务局下一次生成可恢复15个小节的67个业务标题，排除与父级重复标题；依据类不强造业务分析。
- `functions/api/reportexecution.js`：生成及整节返修绑定标题契约；新生成标题也在后续返修中固定，预算扣除标题。旧任务不跨新策略直接返修。
- `md.js`、`report-section-layout.js`：Markdown、HTML及中文序号标题识别、层级和连续编号；页面与Word使用统一结构。
- `aireport.js`、`export.js`：历史版显示“下载本版 Word”；下载只消费选中版快照，异步身份及版本保护，重复点击与失败恢复。历史不混入当前DOM或测算。
- `index.html`：更新受影响脚本缓存版本。未改变财务公式、正式项目事实、原报告版本或签发门禁。
