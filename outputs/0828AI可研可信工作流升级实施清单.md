# AI可研可信工作流升级实施清单

形成日期：2026-08-28
依据：《0828AI_StudyReport_项目综合评估与发展建议_2026-08-28》与当前代码实测

## 一、结论

评估方案总体可采纳，但不能照单重做。当前系统已经具备参数影响预演、白箱复算、受影响章节标记、局部重生成、候选稿接受/拒绝/撤销、报告版本、测算快照、联网证据分级、项目恢复和Agent审计等基础能力。真正短板不是“再增加一个Agent”，而是把已有能力绑定成可核验、可回退、可审签的可信工作流。

本轮采用“先补可信链，再补决策层，最后做企业化”的顺序。

## 二、建议分类

### 1. 已有能力，禁止重复造轮子

1. 参数修改预演、白箱重算和指标差异。
2. 参数变化映射受影响章节，支持人工锁定和选择性更新。
3. AI修改先形成候选稿，支持接受、拒绝、撤销。
4. 报告版本与测算快照、分析快照初步绑定。
5. RAG、Wiki、Excel单元格、联网证据的来源记录。
6. 项目级会话、刷新恢复、暂停继续和项目管理。
7. Agent工具注册、检查点、Token/成本/延迟记录。
8. 项目综合诊断、硬规则异常和敏感性分析。

### 2. 可以立即完成，价值最高

1. **完整报告血缘**：报告版本绑定项目数据、参数集、白箱测算、分析数据、知识库、联网证据、工作流、提示词、模型和审查快照。
2. **四类信息标识**：事实依据、假设/待核、白箱计算、AI分析判断可同时出现在一个小节。
3. **小节可信度**：依据真实来源、待补内容、版本过期、候选修改等确定性因素评分，不让无证据AI文本冒充高可信事实。
4. **指标依赖图**：参数→计算指标→表格→章节→结论，统一现有散落的影响判断。
5. **Evidence/Claim图**：结论句→证据→来源，支持一条证据支撑多个结论和失效影响分析。
6. **提交前可信审查**：集中检查低可信小节、无来源数字、过期资料、测算/正文不一致和待补材料。
7. **结构化项目记忆**：项目事实、关键假设、人工决策、版本里程碑分层保存。

### 3. 需要真实项目或数据后推进

1. 5—20个Golden Projects基准集。
2. Base/Bull/Bear/Stress情景区间和业务阈值校准。
3. 章节可信度与人工审查结果的统计校准。
4. 真实报告结论与证据图的召回率、准确率评测。
5. 50人并发、长报告生成时延和成本基线。

### 4. 需要服务器或组织条件

1. SSO、组织架构、项目级/字段级RBAC。
2. 集中密钥、文件安全扫描、备份恢复和灾备演练。
3. 生产SLO、告警、审计归档和多租户隔离。
4. 内网模型、商业搜索和外部Provider的正式网络策略。

### 5. 当前不建议投入

1. 为提高概念完整度继续拆更多Agent。
2. 在业务闭环未稳定前拆微服务。
3. 无明确收益地继续堆模型数量。
4. 优先做移动端、动画或与可信可研无关的视觉功能。

## 三、六阶段实施步骤

### 第一阶段：可信版本基线（本轮已完成）

- 新增独立 `report-trust.js` 可信度模块。
- 报告版本血缘覆盖十类输入快照。
- 同一正文但知识、证据或审查快照变化时，必须形成新版本。
- 每个小节生成四类信息标签和0—100可信分。
- 报告版本保存小节可信档案和整篇可信汇总。
- 前台生成预览显示“信息类型 + 可信分”徽章。

验收：新增5项可信度测试；全仓库341项测试全部通过。

### 第二阶段：统一指标依赖图（本轮已完成）

- 新增 `report-dependency.js`，形成参数→指标→章节的可执行依赖图。
- 参数修改预演同时显示指标差异、受影响章节、同步策略和人工锁定状态。
- `ProjectWorkflow.impactedSections` 与 Agent 工具共用同一依赖图，旧关键词规则仅作兼容兜底。
- 报告版本保存依赖图摘要，支持判断证据或参数变化的传播范围。

### 第三阶段：结论—证据图和可信审查（本轮已完成）

- 新增 `report-evidence-graph.js`，形成 Claim→Evidence→Source 三层图谱。
- 证据可来自政策/Wiki/RAG、正式材料、Excel单元格、联网依据、数据接口和白箱测算。
- 提交前审计对“无证据数字、证据过期、待补占位和强判断无依据”分别给出阻断或警告。
- 复核页集中显示关键结论、已绑定证据、来源、阻断项和警告；签发按钮执行同一审计，硬阻断未清除时不能签发。

### 第四阶段：决策驾驶舱与情景实验室

- 驾驶舱只展示决策需要的指标、关键风险、敏感参数和资料缺口。
- 情景实验室由白箱引擎计算Base/Bull/Bear/Stress，不由AI编造数值。
- AI只负责解释情景差异、风险来源和行动建议。

### 第五阶段：Golden Projects与持续评测（系统能力已完成，真实样本待入库）

- 新增黄金样本数据表、API、前台候选提交和后台发布/归档/删除/评测工作台。
- 单个项目评测章节覆盖率、关键数字准确率、缺口率、可信度和提交前审计，形成0—100分和通过门槛。
- 只有人工复核后的真实报告才能提交候选；管理员发布后才进入正式基准集，禁止用AI虚构项目填满数量。
- 当前完成的是“可持续装入和重复评测”的系统。正式库达到5—20个项目，仍需后续把已审定真实项目逐一脱敏、发布并跑首轮基准。

### 第六阶段：企业级上线

- 完成50人并发、任务队列、SLO、告警、备份恢复和权限模型。
- 生产环境启用集中密钥、审计留痕、项目隔离和文件安全。
- 以真实项目验收为发布门槛，不以“功能按钮存在”为验收标准。

## 四、本轮功能变化（面向使用者）

1. 以前保存报告只知道“正文对应哪次测算”；现在还能知道它用了哪份项目数据、参数、知识、联网证据、提示词、模型和审查结果。
2. 以前“依据置信度”主要看有没有材料；现在明确告诉用户本节哪些是事实、哪些是白箱计算、哪些仍是假设、哪些属于AI判断。
3. 以前正文没变时系统可能认为无需新版本；现在即使正文相同，只要证据或知识版本变化，也会留下新版本，避免“文字一样但依据已经换了”无法追踪。
4. 以前整篇报告缺少统一可信度摘要；现在版本内保存平均可信分、低可信小节和待关注清单，为后续提交前审查提供直接数据。

## 五、下一步优先级

1. 从已审定项目中选取5—20个，覆盖出租、出售、非居改保并入库。
2. 用真实基准运行模型/规则版本差异，校准80分通过线与关键数字95%门槛。
3. 开展50人并发、报告长任务时延和SLO告警验证。

三项系统能力已形成同一可信闭环；下一阶段不再堆Agent概念，转向真实项目入库、实测和生产运行指标。
