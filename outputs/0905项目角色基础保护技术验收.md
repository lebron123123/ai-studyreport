## 本批实现

- `_project-access.js` 统一项目成员角色判断；原创建者保留所有者身份，失效成员不能通过旧 Agent 授权重新获得访问。
- `_project-members.js` 在 PostgreSQL 事务内修改成员、记录审计、推进项目版本；移除成员或降为查看者时取消该成员在该项目的排队/在途 Agent 任务。角色管理接口复用此入口。
- `projects.js` 支持共享项目读取；查看者不能保存，编辑者不能管理成员；使用项目版本和实时成员条件防止旧保存覆盖新保存。删除、复制仍保留原创建者限制。
- `agentjobs.js`、`agentruns.js`、`_agent-policy.js`、`_agent-enterprise.js` 补充任务创建、读取、重试和执行阶段的当前项目授权检查。
- `auth.js`、`app.js`、`report.js`、`project-manager.js` 接入只读保护和角色展示。刷新时先验证权限；验证中、验证失败或被移除时不恢复成可编辑旧稿，不删除本地草稿。查看者使用安全的纯文本报告/历史版本视图。

## 不能扩大宣称的边界

- 角色变更事务保障针对当前本地 PostgreSQL；缺少事务能力的环境拒绝新成员变更，未证明云 D1 原子等价。
- Project Brain、Investment Ops 等部分旧接口仍维持创建者专属限制，不能宣称所有模块均已支持协作编辑。
- 查看者页面为纯文本安全视图，不代表完整排版/表格/导出体验已经验收。三个真实账号的完整页面邀请、编辑、撤权与刷新流程尚需集成验收。
- 权限检查失败时暂停恢复可编辑状态，是保护措施；网络离线时不会自动开放旧稿编辑。
- 旧接口及其他工作流仍需逐一核查，不能宣称全站授权审计已经结束。
