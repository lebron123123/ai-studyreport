# 公司AI智能体优秀实践融入AI可研系统分步实施方案

> 形成日期：2026年8月25日  
> 依据：《AI应用场景推进计划及进展（8月）》及当前AI可研系统实际代码能力  
> 原则：不为了“像智能体”而增加概念，所有能力必须进入真实项目流程，并具备证据、人工接管、失败回退和可量化验收。

## 一、总体判断

当前AI可研系统已经具备白箱测算、项目级对话、工具调用、RAG/Wiki、规则审查、逐章生成、版本恢复、材料补充和多格式导出等基础，短板已经不是“有没有Agent”，而是以下四点：

1. 生成结论的证据链还需进一步统一和量化；
2. 137个小节的材料完整率、引用覆盖率和人工修改率需要形成统一指标；
3. 数据采集、规则、测算、报告生成等能力需要为服务器部署进一步服务化；
4. 功能很多，但实际项目使用量、准确率、节省时间等业务成效仍需持续积累。

因此，后续升级应围绕“证据化、结构化、服务化、可运营”四条主线推进。

## 三、分步骤实施

## 第一步：统一“证据链式生成与审查”

### 目标

任何重要结论都能回答：检查了什么、证据来自哪里、依据哪条规则、为何得出该结论、应如何修改、由谁复核。

### 实施内容

1. 为生成规则、审核规则和测算规则统一增加规则ID；
2. 每个章节输出关联的文件、Sheet、单元格、知识库页面、数据接口或测算指标；
3. 生成结果统一附带“证据状态”：已确认、待检索、待上传、待人工核实；
4. 审查问题统一输出六要素：检查对象、事实证据、命中规则、判断、修改建议、复核状态；
5. 禁止AI把“待补材料”误写成真实事实。

### 验收标准

- 关键数字100%可以定位来源；
- 硬规则结论100%显示规则ID；
- 无依据的确定性结论数量为0；
- 缺少材料时仍生成可用框架，并准确标出待补位置。

## 第二步：建立137个小节的结构化完整率体系

### 目标

借鉴简历系统的字段Schema，将每个可研小节从“自由文本任务”变成可检查的数据任务。

### 实施内容

1. 每小节定义：必需材料、可选材料、知识库来源、网络来源、数据接口、测算指标、人工输入；
2. 增加章节完整率、来源覆盖率、关键数字覆盖率和人工确认率；
3. 批量上传材料后自动重新解析，并实时更新相关小节状态；
4. 出租、出售、非居改保共用字段底座，差异规则分类型保存；
5. 表格和图片使用模板ID关联，不把大型模板重复写入每条逻辑。

### 验收标准

- 137个出租类逻辑项均有明确材料Schema；
- 上传材料后，受影响小节在页面上实时由红转绿；
- AI能输出完整材料清单Excel；
- 章节完整率与正文实际内容一致。

## 第三步：全面采用“候选结果+人工确认”

### 目标

对高影响输入不由AI静默决定，而是提供候选、依据和差异，让用户确认。

### 实施内容

1. 项目地址提供不少于10个候选并展示行政区、完整地址和匹配原因；
2. 参数来源展示案例中位数、行业规则、专家默认值和正式资料候选；
3. 政策、市场案例、竞品和Wiki引用展示候选来源及统计期；
4. PPT、报告表格和章节表达方式提供模板候选；
5. 记录人工确认结果，作为后续同类项目推荐依据。

### 验收标准

- 所有核心参数均有来源和人工确认标识；
- 地址、案例和政策不再跨区自动采用；
- 用户可以返回上一步重新选择，且后续状态正确恢复。

## 第四步：按“数据层—能力层—业务层”重整服务器架构

### 目标

为服务器部署、50人并发和未来多数据服务接入做好准备。

### 实施内容

1. 数据层：项目资料、知识库、案例库、规则库、模板库、测算快照、数据Provider；
2. 能力层：OCR/解析、RAG、网络检索、POI、测算、审查、报告生成、PPT生成；
3. 业务层：出租、出售、非居改保、项目数据分析、AI办公；
4. MCP/Provider只负责统一能力协议，不重复保存业务逻辑；
5. 增加服务健康检查、超时、重试、熔断、降级和调用链日志。

### 验收标准

- 任一模型或数据Provider故障时可降级并给出明确提示；
- 单个模块更新不会导致全站接口Failed to fetch；
- 50用户并发下生成队列、数据库连接池和AI限流工作正常；
- 每次失败可定位到具体服务和请求ID。

## 第五步：增加反方审查与持续复核

### 目标

系统不仅帮助完成报告，还主动挑战项目假设。

### 实施内容

1. 对租金、售价、出租率、销售进度、成本、工期和融资利率进行反方质疑；
2. 识别“结论先行但证据不足”“引用政策过期”“需求判断缺数据”等问题；
3. 自动生成保守、基准、乐观三类情景；
4. 政策、市场和材料变化后自动预演受影响参数和章节；
5. 用户确认后只更新未锁定章节，保留修改差异和撤销能力。

### 验收标准

- 每个项目至少形成一份关键假设挑战清单；
- 高影响参数均有情景分析或敏感性结果；
- 数据更新后能够准确标记受影响章节；
- 人工锁定内容不会被自动覆盖。

## 第六步：建立真实使用评测与运营看板

### 目标

从“功能很多”升级为“效果可以证明”。

### 核心指标

1. 单项目平均编制时长；
2. 单章节平均生成时长；
3. 生成成功率和失败重试率；
4. RAG引用命中率和证据覆盖率；
5. 人工修改字数占比和章节重写率；
6. 规则审查发现问题数、采纳率和误报率；
7. 测算结果人工复核差异；
8. 月活用户、项目数、导出次数和平均节省工时。

### 验收标准

- 至少使用5个真实项目形成基线；
- 关键指标可以按项目类型、用户和时间统计；
- 每次系统升级都能对比升级前后的质量与耗时。

## 第七步：企业级入口与复用

### 目标

在服务器部署稳定后，把能力嵌入真实办公入口。

### 实施内容

1. 接入集团统一身份和权限体系；
2. 评估企业微信、OA或统一门户入口；
3. 普通用户可提交材料和建议，但正式知识、规则和模板必须管理员审核发布；
4. 部门知识库与个人知识库分离，权限、版本和引用范围清晰；
5. 形成一线使用、管理员运营、规则维护和技术运维四类培训手册。

## 四、推荐实施顺序

| 优先级 | 阶段 | 建议时间 | 原因 |
|---|---|---|---|
| P0 | 第一步：证据链 | 立即 | 决定可研结果是否可信 |
| P0 | 第二步：137小节完整率 | 立即 | 决定真实项目是否能顺利生成 |
| P0 | 第六步：评测指标 | 与真实项目同步 | 没有基线就无法证明升级有效 |
| P1 | 第三步：候选确认 | 持续完善 | 降低错误自动采用风险 |
| P1 | 第五步：反方审查 | 真实项目后 | 提升领导审查价值 |
| P1 | 第四步：服务化 | 服务器部署前 | 保证并发、稳定性和可运维性 |
| P2 | 第七步：企业入口 | 服务器稳定后 | 避免过早扩大使用范围 |

## 五、最终成果形态

最终系统不只是“自动写可研的网站”，而是项目决策智能工作台：

> 用户提交项目和资料后，系统确认位置与关键参数，调用真实数据、知识库和白箱测算引擎，逐节生成带证据的可研初稿；对缺失材料实时提示并允许补充，自动审查规则、数据和文字风险；用户可通过对话修改、锁定、接受或撤销；系统保留项目版本、测算快照和引用来源，并通过真实使用指标持续优化。
