# 非居改保经理批示逻辑消化与实施映射

日期：2026-09-04  
来源：`市税务局第一批合作房源改造为保障性租赁住房项目_阶段稿V2 (1)【更新版】.docx`  
适用范围：非居改保、居改居等住房改造项目；不影响商业改造场景。

## 1. 批示分类结论

### A. 大结构与框架调整

1. 住房改造报告由原13章调整为12章，删除“委托单位及编制单位概况”。
2. 第一章固定为：编制依据与编制说明 → 项目背景 → 项目本体、改造及政策符合性 → 合作模式及期限 → 改造目标、投资及经济效益 → 可行性与必要性概述 → 问题、建议与结论。
3. 市场章改为“需求在前、供给在后”：人口就业 → 职住关系 → 客群画像 → 住房租赁供给 → 竞品租金 → 供需态势结论。
4. 原“改造升级策略及效果”和“项目管理和实施进度计划”合并为“改造运营方案”。
5. 原错误的环境影响章节改为“项目合作模式”，明确合作方式和核心条款。
6. 后续投资、财务、社会效益、风险、结论章节统一顺延并重新编号。
7. 正式层级采用章、节、小节三级编号，运行时按 `1.1 / 1.1.1 / 1.1.1.1` 顺序组织。

### B. 表格体系调整

第一章固定配置6张核心表：

1. 项目基本情况表：地址、面积、楼层分布、拟改用途、现用途、土地年期、竣备时间、交通。
2. 改造前户型/房源现状表：单间、一房、两房、三房、层高、套数、建筑面积、使用率。
3. 政策符合性表：法定改建条件、项目匹配情况及六项合规核验。
4. 改造后户型表：按改造后产品结构列示房型、套数、面积等。
5. 投资估算表：硬装、软装分列，禁止把两类成本混为一项。
6. 经济效益表：运营成本、投资期限、IRR、净利润、NPV，数字只允许引用白箱测算或已核实材料。

其余章节同步配置住房供需、竞品、客群、改造责任、财务、进度、风险、合作核心条款等8张标准表，共14张住房改造逻辑模板。所有项目专属数值保持空白，不把税务局项目数字固化为通用模板。

### C. 生成逻辑调整

- 住房改造默认目标为保障性租赁住房，禁止混入商业市场、招商、商业业态和配套商业内容。
- 政策依据逐条列明，不再笼统概括；项目背景和政策背景压缩，避免重复。
- 删除“改造动机分析”和“资质证书等资料待补”等无效或不正式表达。
- 必要性只做政策、经济、社会和项目层面的凝练论证，不使用图表堆砌。
- 市场分析按区—街道—项目3公里逐层展开，补充净人口流入、租赁条件和竞品比较。
- “供需平衡分析”统一改为“供需态势分析”，避免在证据不足时作伪精确平衡判断。
- 多点位按重要程度先后整体论证，正文不再出现“主项目/次项目”标签。
- 合作主体使用真实公司名称，禁止笼统写“甲方/乙方”，并明确改造与运营责任。
- SWOT采用定量证据与定性判断结合的简洁表达。
- 第一章目标篇幅7—8页，原则上不超过10页；正文避免重复、空话和无关POI罗列。

### D. 小段落与措辞调整

- “住房租赁市场”替代商业市场口径。
- 分散式租赁房源明确包含“商品房、住宅等”。
- 区位与交通在结论层概括；不采用未经正式来源确认的POI。
- 项目概况中的“投资规模”移出项目本体描述，归入投资与经济效益位置。
- 竞品表前置到竞品分析，竞争定位在项目定位章承接结论，不重复造表。

## 3. 税务局项目的实际使用路径

1. 打开原税务局项目并进入“AI可研生成”。系统加载住房改造正式逻辑后，会把旧13章草稿迁移到新12章结构。
2. 原有正文按章节名、小节名和受控别名迁移；不会因章节顺延而把正文错放到别的小节。
3. 结构改名或逻辑有变化的小节显示“待同步”；锁定的小节显示“已锁定待复核”。
4. 点击右侧“生成受影响候选稿”。有旧正文的小节按新版逻辑局部修订；新增小节按新版逻辑生成初稿。
5. 系统只生成候选稿，不覆盖当前正文。逐节对比后选择接受或拒绝；未受影响小节保持不动。
6. 接受后的项目级成果继续进入复核、Word导出和版本链；若要沉淀为后台通用规则，仍需通过自动评测和管理员发布，防止单个项目意见污染全部项目。

## 4. 删除与保留边界

- 从住房场景删除：委托/编制单位小节、商业市场与业态逻辑、配套商业改造、错误环境影响章节、改造动机、无效资料提示。
- 从通用改造基线不物理删除：商业改造仍需要的原章节与逻辑。采用场景过滤而不是破坏性删除，确保旧商业项目兼容。
- 不固化：税务局项目名称、地址、面积、租金、投资额、合同期等项目专属事实。
