# AIStudyReport：项目全周期工作台优先实施步骤方案

形成日期：2026-09-07（本机日期）。

依据：用户提供的《0908_AIStudyReport_专业使用与全周期及AI可研完善总方案.md》，重点采用第8、11、14、16、17章；结合当前本地工作区核查，不把文档中的建议当作已经实现的能力。

核查基线：Git HEAD `f8a1bed`，另有较多未提交修改。本文是实施计划，不是完成报告；本轮未修改业务代码、数据库或正式资料，未提交或推送 Git。

## 一、结论：采纳方向，但调整实施次序

建议安排12步，**前6步全部围绕项目全周期工作台**，先让它真正成为独立、清楚、能办事的项目入口；随后完善AI可研质量，再延伸实施投后和真实验收。

不建议推倒重建，也不把“60项全部90分”作为这轮开发目标。当前更有价值的目标是：

1. 投资人员能找到项目、看清当前工作、进入对应页面，不必所有事情都回到AI可研。
2. 页面切换不修改业务状态，不误触发生成，不丢失草稿、候选稿和后台任务。
3. 项目事实、采用方案、工作阶段、正式成果在不同入口保持一致。
4. 决策数字和报告依据可核验，错误或缺失不能被显示成“已通过”。
5. 先跑通一个真实项目，再扩大场景和部署范围。

**执行次序与安全优先级分开：**第1—2步的只读导航、布局可以先交付；第3步的项目边界、第5步的可信指标，以及第12步中的数据库测试门禁必须前置并行修补。不能以“先做好界面”为由继续扩大有风险的跨项目写入或正式决策功能。

## 三、先固定工作台结构，避免再次挤在一起

### 3.1 三个层次，不混用

|层次|解决的问题|展示内容|
|---|---|---|
|全局层|我要找哪个项目、看哪些项目的汇总？|项目库；真正跨项目的数据、决策、成果汇总|
|单项目阶段层|这个项目在某个阶段有哪些事情要办？|八阶段工作页面、该阶段待办、所需资料、相关成果、主操作|
|单项目工具层|我要找这个项目的某一类对象？|资料、事实、测算、报告、任务风险等完整管理页面|

全局顶部入口如果实际只显示当前项目，必须明确标为“本项目”，不能用“全局数据中心”的名称制造误解。跨项目汇总未实现之前，不先做假入口。

### 3.2 八个阶段是并列页面

项目寻找 → 初步研判 → 立项 → 可研与尽调 → 投资决策 → 项目实施 → 投后管理 → 退出与复盘。

这是生命周期排列，不意味着每个项目必须无条件走完，也不意味着点到后面的页面就已经完成前面的审批。长期持有项目可以持续投后管理，不强迫进入退出阶段。

### 3.3 单项目侧栏是另一组并列工具页

- 项目总览。
- 资料与研究：资料与附件、项目事实与证据、参数与测算、市场与区位。
- 决策与执行：方案与决策包、行动与风险、任务与计划。
- 成果：报告与版本、复核与验收。
- 项目设置：成员权限、项目配置、归档；删除等危险操作放入明确的管理入口。

允许把关联很强的内容设为页内子页签，例如“参数与测算”内保留数据注册表、参数、结果，不能因为合并导航而删掉功能。

**阶段页与工具页共用同一批数据，不各建一套。**例如在“可研与尽调”看本阶段资料，点击详情仍进入统一资料页；从侧栏直接进入资料页，默认看全项目资料，阶段筛选必须清楚显示。

### 3.4 必须分开的三个动作

|动作|用户感受|是否写业务数据|
|---|---|---|
|查看某阶段|点一下就换页面|只保存本人视图偏好，不改项目阶段或审批|
|更正项目工作阶段|有权限者在页头调整，显示已保存及可撤销|写唯一工作阶段、版本及日志；不自动通过阶段门|
|正式提交、通过、退回或豁免|在对应业务对象中明确操作|检查实际授权、证据和版本；留下正式记录|

“所有者/编辑者/查看者”是项目协作权限，不自动等于公司正式审批职责。

## 四、分步骤实施清单

### 第1步：阶段一键浏览与独立页面恢复【工作台优先】

**要做：**点击阶段只切换阶段页面；在现有路由上增加浏览阶段，区分“正在查看”和“项目工作阶段”；兼容旧链接。按用户和项目隔离视图偏好，支持刷新、返回、前进、复制链接和快速切换。

**保留：**正文、候选稿、编辑锁定、后台生成任务与其执行快照。切页面不得触发重生成、重算或采用方案变化；旧资料没有阶段标签时放入“项目共用/待归类”，不能消失。

**验收：**连续点击八阶段不调用阶段写接口；查看者也能浏览其有权内容；切项目后的迟到响应不会串页；保存草稿失败有明确处理，不能静默丢稿。

**责任模块：**`project-manager.js`、`project-workspace-ui.js`、既有路由恢复机制。对应文档F19及第14.7节。

### 第2步：阶段内容、主操作与清爽布局【工作台优先】

**要做：**沿用现有项目库/工作区分离和窄侧栏，统一导航配置；页头只保留项目身份、当前工作阶段及一个主要动作。摘要、历史、明细各归其位，详细日志、技术JSON、运维指标不挤在业务首页。

|阶段|主工作内容|主要操作示例|
|---|---|---|
|项目寻找|线索、来源、资产范围、联系记录|完善项目线索|
|初步研判|基本条件、限制、资料缺口、初算|继续初判|
|立项|研究任务书、范围、负责人、里程碑|完善立项资料|
|可研与尽调|事实、测算、报告、复核问题|继续报告或处理候选稿|
|投资决策|采用方案、决策包、条件与意见|准备或查看决策包|
|项目实施|计划、变更、验收及交接|处理计划或变更|
|投后管理|经营数据、预算偏差、风险与预测|录入数据或处理偏差|
|退出与复盘|持有/退出分析、复盘和归档|编制复盘|

主操作由实际状态、权限、已接通的能力决定；不强行每阶段放一个AI按钮。尚未具备的正式操作清楚说明条件，不能用空按钮冒充功能。

**验收：**旧功能都有明确新位置；项目列表不长期占据工作区一半；长表格可局部滚动；空项目、加载中、局部失败、只读成员均可理解；返回项目库保留筛选与阅读位置。

**责任模块：**现有项目页面、样式及动作适配入口。F20/F21部分已改善，本步是完善而非重做；处理F22。

### 第3步：项目隔离、成员权限与唯一工作阶段【工作台上线基础】

**要做：**阶段门、里程碑、成果等对象的更新与关联校验都限制在授权项目内；旧Brain/Ops接口接入统一成员权限，但先分清个人草稿与项目共有记录，不能简单删除创建者限制。

选定唯一工作阶段写入口，其他入口只读投影；新增版本冲突校验和同事务审计。先列出历史双来源冲突，再按明确规则迁移；未知项标待核，不推断“已批准”。更正工作阶段不能顺带通过正式条件。

**验收：**提交其他项目的对象ID不能修改对方数据；只读者不能写；编辑者不能凭传入`passed/waived`越权；撤权后重新读取、继续写入和迟到结果均受限制。迁移可重复、冲突可见、有回退方案。

**责任模块：**`functions/api/projectintelligence.js`、`projectbrain.js`、`investmentops.js`及统一项目授权模块。对应F01/F07/F08/F17。

**业务边界：**可先落实权限框架与保守默认；正式审批人、豁免权、管理阶段更正权由公司确认，不能擅自赋予某角色。

### 第4步：场景资料清单、真实缺口与统一项目进度【工作台业务能力】

**要做：**按资产场景和阶段配置必需、条件必需、可选、不适用资料；未创建的必需字段也计入缺口。把“没录入”“未核实”“口径冲突”“不适用”分开，不再因为表里没有记录就显示已齐备。

建议先用税务局这一批住房改造项目作为候选试点，前提是资料可用且获准用于验证。保留既有租赁、销售、改造计算引擎，不为场景分类改坏旧项目。

事实补齐单位、时点、项目/点位范围、原件位置及确认人；不同来源冲突保留双方。“已确认假设”仍是待验证假设，不能变成客观事实。首页、资料页、AI上下文使用同一份缺口与状态投影。

**验收：**只有项目名称的空项目不显示100%资料齐备；新加必需项能显现；多点位不串事实；统计失败显示暂不可用而非0，当前分页数量不能冒充全部数量。

**责任模块：**`project-brain.js`、`project-intelligence.js`、事实/数据注册及场景规则。对应F06和第9章。

### 第5步：可信方案比较与可核验决策包【工作台核心】

**要做：**方案引用服务端真实、属于本项目的测算快照；用户修改假设后重新计算，不允许客户端随意传指标就标成白箱结果。所有入口明确使用采用方案ID，不以“列表第一项”代替选择。

全投资IRR、资本金IRR、静态/动态回收期分别保留；比较前核对币种、单位、时点、现金流范围、含税口径。缺失、非有限值及不可比明确提示，不能拿指标键数量或来源ID数量代替验收。

决策包绑定事实、方案、测算、报告和依据版本，列出缺口、限制及待处理条件；“资料齐备”“专业复核”“正式批准”分别展示。

**验收：**伪造快照、指标或项目ID被拒绝；非数值和未知指标不通过；两类IRR不混比；采用方案不在第一项时仍各处一致；不能用无关或不存在的证据放行决策包。

**责任模块：**`investment-ops.js`、`functions/api/investmentops.js`、`project-intelligence.js`及现有计算快照。对应F02/F03/F04/F09。

**前置要求：**可信指标校验属于P0修补，与第1—3步并行，不等到决策界面扩展后才处理。

### 第6步：会议纪要落到任务、风险和条件【工作台执行能力】

**要做：**同一句话可以同时形成风险、待办和决策候选；记录责任人、截止日、来源句及项目归属。先给人核对，再形成正式任务，不让AI解析直接变成业务批准。

按会议版本与来源项建立稳定标识，任务、风险、候选及确认记录在一个事务中保存；空选就是不提交，不能变成全部提交。行动挂到阶段与里程碑，关闭时保留完成依据。

**验收：**重复点击、刷新重试不生成重复任务；中途失败不留半批记录；同一句风险加行动能建立关联；编辑过的会议只处理明确新增或变更项。

**责任模块：**`investment-ops.js`、`functions/api/investmentops.js`及工作台行动页。对应F10/F11。

**到这里的交付目标：**工作台能够完成找项目、看阶段、查资料、补事实、比方案、看决策包、落实会议行动。它不再只是AI可研的外层菜单；但并不等于实施和投后已全部完成。

### 第7步：原件—资料库—报告结论的证据链【AI可研基础】

**要做：**复用已有审核发布与RAG，把原件、解析文本、检索片段、项目事实和报告引用连接起来。政策原文、解读、经验卡及文件格式分别标注；不是所有联网资料都做成经验Wiki。

为文件和政策保留来源网址、版本、发布时间/适用范围及待核状态。报告关键判断要能回到相关原文片段、页码或计算结果，不能把整节所有来源挂到每一句上冒充支持。

支持、反对、背景资料、尚未核实分开。长文件或全文未处理部分明确显示范围，不能只检查前40句却声称全文覆盖；政策有效性和适用性仍需专业核对。

**验收：**给结论挂无关材料不能得到“已核实”；关键依据在长材料后部仍可找回，或明确未处理；移除/更新来源后，引用状态可追溯且不会静默维持有效。

**责任模块：**资料检索与发布接口、`report-evidence-graph.js`及引用适配。对应F05/F13。

### 第8步：章节论证、全文数字及可解释质量检查【AI可研专业性】

**要做：**把章节要求组织为“要回答什么—必需事实—证据—可用测算—允许假设—缺失时怎么写—检查项”，替代对所有章节固定500—800字的规则。全篇语言限制继续单独管理，不重新塞回每个小节。

所有涉及数字的正文、表格和摘要都接可信测算与事实，补中文数字、金额、单位和跨章口径检查；总论与结论最后依据核验结果生成。段落没有可信输入时明确待补，不让模型编数。

把启发式94%等改为证据完整度、数值一致性、待复核问题等分项状态；模型、引擎、规则及解析器版本从真实执行记录取得，不硬编码假血缘。

**验收：**同一数字在摘要、正文、表格冲突会提示；没算过不显示0；未核实不能显示高正确率；章节输出可追到实际采用规则及数据。

**责任模块：**`report.js`、`report-trust.js`、章节规则和真实执行清单。对应F12/F14/F15及第11—12章。

### 第9步：编辑恢复、复核冻结与Word成果【AI可研交付】

**要做：**在既有候选稿、版本与冻结能力上补齐稳定段落标识、版本冲突提示、受影响范围和逐项专业复核。接受、拒绝、保持原样必须后台确认保存后才显示完成；锁定正文不因规则变化被改写。

正式成果及其引用快照长期保留；恢复旧版生成新工作稿，不覆盖已签发历史。独立复核、正式审批和自动检查分开，审批绑定服务端冻结内容与实际授权。

复用既有Word导出，针对真实报告补目录、标题编号、表格、脚注/来源、横向页及版本标识；不只以成功生成文件为验收。

**验收：**批量接受后刷新不回到待接受；断网、重复提交、并发编辑及超大报告不静默丢失；签发后仍能查到原内容；实际打开Word核对数字、表格和版式。

**责任模块：**报告保存与复核、冻结/归档、现有导出。对应第11章、第14.6节及T12—T15。

**边界：**正式多人审批框架能开发，但组织职责、签发效力和实际Word交付标准需要业务负责人确认。

### 第10步：批准基准、项目计划与变更影响【全周期深入】

**要做：**明确区分当前采用方案、原批准基准、批准调整版、最新预测。复用第5、9步的可信快照与冻结版本；批准基准保存依赖清单，不随普通编辑变动。

把工期、投资、开业/起租日期和里程碑连接起来；变更先预演影响，再按实际授权处理。正式通过条件、附条件、退回、豁免有独立依据，不能靠阶段导航生成。

**验收：**租金、面积、工期改变只影响准确识别的项目与章节；原批准版不变；任务和现金流变化有对应关系；未批准预测不冒充批准调整。

**依赖：**第3、5、9步。公司尚未确认审批规则时，可以交付版本、对比、预演和申请框架，不自动启用正式批准。

### 第11步：投后实际数据、偏差及跨项目只读汇总【全周期深入】

**要做：**先做人工或表格导入经营实际数据，记录期间、口径、来源与确认；按批准基准和最新预测展示偏差，区分量、价、时间、口径影响及未解释差额。

合同承诺、履约、应付、已付分层，不直接相加造成重复计数。跨项目汇总先做只读，并统一币种、单位、期间和权限；IRR不简单平均。复盘中的经验候选仍走知识审核，不直接把个案结论变成公司通用规则。

**验收：**重复导入可识别；修正实际数留版本；不能用预测覆盖真实数；汇总只能看授权项目；缺外部数据时不展示虚构经营指标。

**依赖：**第10步和真实经营数据。正式OA、财务、资产系统对接放到接口和授权具备之后，不在本轮重造那些系统。

### 第12步：可信评测、发布门禁与真实试点【贯穿全程，最后总验收】

**立即前置的代码：**统一CI数据库配置，使必要的PostgreSQL事务、权限和恢复测试实际执行；缺必需数据库不能静默跳过后显示全通过。把旧Investment Ops评测入口接到已有受信评测器，客户端自报通过、缺错误数不得作为生产验收证据。

**逐步补齐：**将前述风险转换成行为用例；对权限、事务、幂等、版本冲突、撤权、Worker失租及迟到结果做真实数据库与浏览器测试。负载、备份、恢复和机房部署沿用已有工程能力，按实际缺口补，不另起一套运维平台。

**最后业务验收：**先一个真实住房改造项目，再一个独立项目及不同角色；建立业务负责人确认的Golden、开发验证集和独立留出集，避免同项目不同章节泄漏到两边。记录专业问题、用时、成本和失败例，而不只报测试数量。

**验收：**已知风险均有修复和行为证据；客户端伪造评测不能通过；正式成果与依据可追溯；生成、复核、导出、刷新恢复及备份恢复实际跑通。

**不能由代码代替：**业务基准确认、专业判断、审批责任、独立样本、真实经营数据与持续运行记录。完成代码不等于已经取得企业级正式验收，也不自动提高到90分。
