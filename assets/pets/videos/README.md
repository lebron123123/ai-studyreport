# 蓝喵 / 安小居双形态视频动作维护说明

正式网页素材共41个MP4、54个逻辑片段（蓝喵32段、安小居20段、双向变身2段），集中由根目录 `pet-video-manifest.js` 注册。原始生成文件按角色保留在 `outputs/pet-video-source/蓝猫/`、`outputs/pet-video-source/安小居/`，网页不直接引用原片。蓝喵使用真实双向转身；安小居左右方向共享完整三段跑步链并由Canvas整段镜像，禁止只镜像单个H1锚点。

## 单视频替换

1. 只替换 `assets/pets/videos/` 中对应的 MP4，建议文件名版本递增，如 `cat-wave-out-v2.mp4`。
2. 只修改 `pet-video-manifest.js` 对应 clip 的 `src`、`version`；如果亮帧长度变化，再单独调整该 clip 的 `trimStart`、`trimEnd`。
3. 不修改动作名称、姿态或分段顺序时，其余视频无需重新处理。蓝喵、安小居和双向变身各自拥有独立clip，后续返工只替换一个文件和一个注册项。

## 亮闪帧处理

源片不删除。播放器按每个 clip 的 `trimStart` 和 `trimEnd` 跳过首尾更亮的生成锚点帧，并在新片段内部帧就绪后才切换画布。当前默认首尾各跳过0.14秒；应根据单片抽帧结果独立微调。

相邻MP4即使同为H0/H1，角色位置、曝光和毛发边缘也可能略有差异。运行时不再把旧帧和新帧交叉混合：播放器保留上一段末帧，等下一段首帧就绪后直接做动作匹配切换，避免任何双猫虚影。若源视频本身存在虚影，必须独立裁剪或重新生成该片段，不能用网页叠帧掩盖。

## 随机动作与姿态

动作池采用加权洗牌且禁止连续重复；跑步由3张提高到6张，在15张视频动作牌中占40%（原为25%），每次沿长方形路线推进一边，因此左右、向上、向下四个方向都会更频繁出现。跳跃保留3张。H0坐姿动作与H1站姿动作随机相遇时，播放器自动插入“坐下”或“起身”，保证姿态链连续。宠物按钮及AI问答面板保持原入口不变。

动作之间仅保留0.18～0.50秒衔接间隔。水平跑在`runStart`播放1.85秒、猫咪真正迈出第一步后开始网页位移，由`runStart`剩余部分和`runLoop`共同完成长边，`runStop`只负责原地刹停；跳跃在`jumpUp`播放2.15秒、猫咪完成蓄力并开始离地后执行3.65秒`screen-hop`，位移在落地过程完成，后续站稳画面保持固定。网页不额外改变纵坐标。向上、向下跑的主片段从首帧就是有效步态，因此方向专属延迟保持0。

每次动作有独立位移令牌和毫秒时间戳；连续两次抽中同名动作时，上一轮尚未触发的延迟定时器自动失效，不得提前启动下一轮位移。

长方形路线按四个角顺序持续推进：上边向右、右边向下、下边向左、左边向上；反向随机时按相反顺序运行。上下方向素材已接入，`directionalRun.verticalAssetsReady=true`，不再通过旋转或侧面滑动伪造。

向上跑采用`cat-run-up-entry-v1.mp4 → cat-run-up-v1.mp4 → cat-run-up-exit-v1.mp4`三段连续姿态链。入场和收尾只做原地转向；网页向上位移仅在`cat-run-up-v1.mp4`播放期间执行，避免转身阶段整体滑动，并保证背面步态结束后通过真实视频恢复H1。

向下跑采用`cat-run-down-entry-v1.mp4 → cat-run-down-v1.mp4 → cat-run-down-exit-v1.mp4`三段连续姿态链。这两段新增入场/收尾就是此前为消除抽帧补做的两个猫咪视频：侧面H1先真实转入正面步态，主跑完成后再真实恢复侧面H1；网页位移只绑定中间主跑片段。

安小居当前启用原地休息、原地翻滚、跳跃、四向跑动四类视频动作。向右/向左均使用`anjuRunEntry → anjuRun → anjuRunExit`完整三段链，向左对整条链镜像；向上使用真实`anjuRunUpEntry → anjuRunUp → anjuRunUpExit`，向下使用正面专属视频。2026-08-31起，横向收尾与向上入场改用正向生成的v2素材，旧倒放片已删除，禁止再通过时间倒放制作跑步入场或收尾。安小居保持约60%驻留时间，蓝喵约40%。

双向变身分别注册`pet-morph-cat-anju-v1.mp4`与`pet-morph-anju-cat-v1.mp4`。倒放衍生文件必须离线生成并作为独立素材接入，网页不在运行时倒放；两段都执行H0/H1姿态契约和首尾裁剪，变身后直接进入目标角色自己的动作池。

## 鼠标真实注视与靠近互动

蓝喵和安小居各使用一段6.08秒眼球方向合集源片。清单通过独立`trimStart/trimEnd`时间窗无损切出“看左/回正、看上/回正、看下/回正”6段逻辑片。蓝喵右看模拟片观感不合格，已从清单删除；鼠标位于蓝喵右侧时暂时保持正视，等待真正右看素材。安小居暂时保留双眼ROI右看。方向变化时固定先回正再看向新方向，避免瞳孔瞬跳。

鼠标进入330像素感知范围后暂停随机动作，按角色支持的方位播放真实眼球片并保持末帧；方向稳定约0.25秒后才切换，鼠标离开后继续保持约1.4秒再播放回正片并恢复动作池。进入150像素范围并稳定停留1.1秒后，蓝喵复用挥爪/跳跃，安小居复用跳跃/翻滚；互动有6.5秒冷却，点击宠物仍只打开AI问答。

每个视频分段同时使用媒体 `ended` 事件和6秒超时保险。动作结束时如果恰逢鼠标悬停、页面点击静默期或短暂忙碌，调度器每450毫秒重新检查；条件恢复后自动继续，不能直接进入无定时器的永久休息态。

网页位移另有独立的结束时间戳。即使某段生成视频的实际时长短于清单估算，动作收尾也必须等待 CSS 位移结束后才能移除 `pet-moving`；禁止用视频 `ended` 事件提前收尾，否则浏览器会直接采用终点坐标并造成上下左右瞬移。

## 已处理问题与固定解法

| 问题 | 根因 | 固定解法 |
|---|---|---|
| 视频像静态图片 | 位移早于首个已解码视频帧 | 首帧解码成功后才显示和启动动作 |
| 首尾亮帧一闪 | 即梦首尾锚点曝光高 | 每片独立设置 `trimStart/trimEnd`，不修改其他片 |
| 双猫、虚影 | 相邻片交叉淡化或源片自身重影 | 运动片默认动作匹配硬切；源片虚影必须裁剪或重做 |
| 跑跳整体滑动 | 网页位移覆盖蓄力、落地或刹停阶段 | 位移只绑定真实迈步/腾空窗口，入场和收尾原地播放 |
| 动作结束瞬移 | 视频先结束并提前移除移动样式 | 记录独立位移结束时间，位移完成后才收尾 |
| 镜像换向跳帧 | H1与镜像H1直接切换 | 使用完整真实转向视频，不切静止镜像帧 |
| 向上跑结束抽帧 | 背面步态直接切侧面H1 | `runUpEntry → runUp → runUpExit`三段式 |
| 向左跑接向下跑跳帧 | 侧面朝左H1直接切正面步态A | 增加向下跑入场；同时增加收尾恢复侧面H1 |
| 动作永久卡住 | 悬停、问答或页面静默清除了调度 | 条件恢复后定时重试，动作令牌隔离旧任务 |
| 新视频牵连全部动作 | 动作和素材耦合 | 每个 clip 独立文件、版本、裁剪和姿态契约，单片替换 |
| 头顶小点、局部短暂增生 | 生成模型在少量中间帧新增了局部结构 | 优先用相邻干净帧做局部ROI逐帧修复并羽化边缘，保留原音频和时长；修后执行五点及完整解码检查，无需为小瑕疵重新生成 |
| “活动”按钮点击后反而休息 | 按钮显示当前状态而不是点击后的命令 | 活动时显示“休息”，休息时显示“活动”；标题同步写明目标角色和点击结果 |
| 不知道当前宠物能做什么 | 快捷工具只有开关，没有按角色动作入口 | 悬停“活动/休息”在右侧展开动作菜单；蓝喵8项、安小居4项，点击后只执行所选视频动作 |
| 安小居跳跃中点卡帧 | 正放尾部和倒放头部各保留约1秒最高点静止画面 | 对称裁掉重复最高点静止段，按实际倒放时长对齐同一动态最高点，不重新编码正式源片 |
| 安小居先原地跑再追位/像瞬移 | 网页等4秒入场片播完才开始移动，且短位移窗口速度过快 | 横向与向上均在入场片首个真实迈步帧开始位移，覆盖入场主跑；向下按正面片真实起步点移动，收尾保持原地 |
| 点击变身没有反应 | 工具栏失焦在0.3秒后启动随机动作，抢占并取消变身视频 | 变身开始前解除悬浮冻结，变身期间禁止随机动作调度；完整播放后才切换角色动作池 |
| 操作工具栏后四向跑瞬移 | 悬浮时写入的`pet-paused`未解除，后续`left/top`失去过渡 | 工具栏退出、手动变身及恢复调度时统一解除冻结；动作播放期间仍用令牌防止旧任务补坐标 |
| 中途恢复出现斜跳或跨角 | 当前点不在标准角点时同时修改`left`和`top` | 长方形每段强制单轴移动：水平只改`left`，垂直只改`top`，下一段再转向 |
| 倒放跑步像腿往后跑 | 时间倒放颠倒了落脚与蹬地的动力顺序 | 重新生成正向收尾/入场视频；空间左右方向可整段水平镜像，但跑步视频不得做时间倒放 |
| 看右时整只宠物翻面 | 直接镜像眼球合集会同时翻转尾巴和身体 | 仅在双眼ROI内镜像真实瞳孔片段，角色其余区域保持原方向 |
| 拖动宠物时控制框留在原位 | 控制框是独立的`position:fixed`元素，只在显示和窗口缩放时定位 | 拖动期间按动画帧重新计算控制框坐标，释放后保持最终位置 |

## 相邻动作验收

单片五点检查通过不代表动作链通过。每次接入必须额外核对相邻两片的“尾部5帧 + 头部5帧”，并在正式页面覆盖长方形顺、逆两个方向的8个拐角。侧面H1、正面步态、背面步态是不同姿态，必须用真实入场/收尾视频连接，不能只在清单中都写成H1。

安小居沿用同一播放器和验收流程，但必须建立独立基准色、姿态状态、首尾帧、素材清单和降级图片。新增或返工只替换对应视频，不重新生成整套动作。
